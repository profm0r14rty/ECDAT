# ECDAT Project Progress

## Batch 1 Summary

ECDAT's scanner core (Batch 1) is complete and tested end-to-end. It now
discovers cryptographic artefacts in source code across Python, JavaScript,
Java, Go, and C/C++ via regex signatures, assesses each artefact's post-quantum
risk using Mosca's inequality (with key-size- and path-based heuristics),
recommends NIST post-quantum replacements (ML-KEM, ML-DSA, SLH-DSA, AES-256),
and exports a real CycloneDX 1.6 CBOM report plus a frontend-friendly summary.
A CLI entrypoint (`python -m ecdat_core.cli scan <path>`) ties the pipeline
together, and an end-to-end test scans a mixed-language `demo_repo` fixture to
prove critical and quantum-safe outcomes flow through to a structurally valid
CBOM. The full suite stands at 92 passing tests (2 network-gated tests
deselected by default).

## Batch 2 Summary

ECDAT's FastAPI backend (Batch 2) is complete and tested end-to-end. It now
exposes the entire scanner pipeline as a REST API: `POST /api/scans` creates a
queued scan run and executes it in the background (FastAPI `BackgroundTasks` —
no Celery, keeping infra lean for the hackathon deadline), with Redis holding
the `scan:{id}:status` job keys and Postgres persisting the full ScanResult
via SQLAlchemy 2.0 ORM rows managed by a repository layer and Alembic
migrations. The API never duplicates `ecdat_core` logic — it calls
`ecdat_core.cli.run_scan` / the risk engine / CBOM exporter directly and
persists the result. Read paths reconstruct the ScanResult from persisted rows
on every request, so per-artefact risk overrides applied via
`PATCH /api/scans/{id}/artefacts/{detection_id}` are reflected everywhere,
including the CycloneDX 1.6 CBOM download. Docker Compose wires the whole
stack (postgres + redis + api, 3/3 healthy, entrypoint auto-migrates). A
